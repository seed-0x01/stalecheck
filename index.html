How to read this, honestly

Error direction 1 (missed stale claim): a figure within 100 characters of a word like “was / deleted / seed / verified / 2026-11-17” is treated as a dated record and is not surfaced. A genuinely current claim written near a date would be missed. This bias is deliberate: it keeps the review list small, at the cost of a possible miss.
Error direction 2 (false alarm): an unlabelled figure is surfaced for a human to review, not auto-failed. A perfectly correct current number can appear in the list — the tool reports what it cannot date, not what it knows is wrong. Only a dead link or a drifted embedded snapshot flips the verdict to FAIL.
Two exclusions, disclosed: stalecheck.html is not graded (grading its own quoted examples would recursively escape them), and the sidecar's dynamic routes (/llms.txt, /inbox, /api/*) are not treated as dead links — they return HTTP 200 but are not files on disk. An embedded snapshot whose date is printed in the visible text is a dated record, not a defect; one whose date lives only in the JSON is flagged.
This tool does not fetch the live chain. It compares files to files. The number that matters is the one your browser derives from balanceOf; if a page disagrees with that, the page is wrong.
